# OpenAI 为什么要合并 Codex 和 ChatGPT：知识工作的入口正在重做

> “OpenAI 里用 Codex 的，不只是工程师。”

> “AI 把产品开发流程反过来了：先做出东西，再判断它是否值得存在。”

> “未来最稀缺的职业能力，可能不是写代码，而是品位。”

Andrew Ambrosino 是 OpenAI Codex desktop app 的产品和工程负责人。Lenny's Podcast 这期访谈讨论的，不只是一个开发者工具如何增长，而是一个更大的问题：当 AI 可以写代码、做原型、操作浏览器、调用工具时，知识工作的入口会不会被重新设计？

OpenAI 正在把 Codex 的经验带进 ChatGPT，也在把 ChatGPT 的通用入口能力和 Codex 的行动能力合到一起。表面看是产品线合并，深层看是工作方式改变：AI 不再只是回答问题，而是开始成为你开始工作、结束工作、协调工具和推进任务的桌面中枢。

![访谈开场展示 Codex 的增长与采用：它已经不只是开发者工具，也开始进入数据分析、研究和知识产物工作流。](images/01.jpg)

## Codex 的变化，不是“会写代码”这么简单

Andrew 提到，Codex 在 OpenAI 内部已经接近成为每周都在用的工具，而且不只是工程师。法律、研究、产品、设计、运营等不同职能的人，都在用 Codex 处理自己的工作流。

这件事很关键。一个工具如果只服务程序员，它的边界是开发者效率；但如果非工程岗位也开始依赖它，它就不再只是 IDE 或 CLI，而是在向通用知识工作工具靠近。

Codex 的早期定位是 coding agent，但它真正打开想象力的地方，是它能读文件、组织信息、生成 artifact、操作浏览器、和桌面上的工具协同。写代码只是其中一种能力，背后更大的能力是“让 AI 进入你的工作现场”。

## 产品开发流程被 AI 反过来了

传统产品流程通常是先调研、写文档、画设计、做评审，再进入工程实现。Andrew 认为，AI 正在把这套流程反过来：当原型和代码变得足够便宜，团队可以更早把想法做出来，再围绕真实产物进行判断。

这听起来像“PRD 死了，原型万岁”，但 Andrew 的观点更细。原型不是万能答案。有些模糊问题需要先用文档建立产品清晰度，否则一个看起来完整的原型，会过早把讨论锁进某个方向。

AI 让原型变便宜，也让坏原型变得更危险。因为它们可能看起来像已经上线的正式产品，让人误以为很多问题已经被解决。真正重要的不是更快做出东西，而是知道什么时候该写文档，什么时候该做原型，什么时候该停止被一个漂亮 demo 诱导。

![Andrew 强调，AI 时代的产品流程不是取消文档或设计，而是重新判断哪种媒介最适合当前问题。](images/02.jpg)

## 品位变成职业能力，不是审美口号

访谈里反复出现一个词：taste，品位。

Andrew 说品位不是单纯的审美偏好，也不是“我觉得好看”。在 AI-first 工作环境里，品位更像一种筛选能力：知道该做什么，知道怎么呈现信息，知道一个原型什么时候只是噪音，什么时候已经摸到了真正的问题。

当 AI 可以生成很多方案，人的价值就从“能不能产出”转向“能不能判断”。你可以让模型一次生成 90 个原型，但真正困难的是从中看出哪一个方向值得继续，哪一个只是表面完整，哪一个暴露了真实用户需求。

这也是为什么 Andrew 认为品位会变得更重要。AI 降低了执行成本，却提高了判断成本。过去团队缺的是产能，未来团队更缺的是能把大量可能性筛成正确方向的人。

## AI 仍然不擅长设计，因为设计很难评分

Lenny 问了一个很多人都有感的问题：为什么顶尖前沿模型仍然不擅长设计？

Andrew 的解释很实在：软件更容易验证。代码能不能运行、测试能不能通过、行为是否符合预期，这些都可以形成相对明确的反馈循环。但设计不一样。什么是好设计，包含文化、语境、信息呈现、节奏、信任感和人类反馈。

这不是说 AI 永远做不好设计。Andrew 也认为模型会变得更擅长设计。但设计的难点不只在视觉，而在软件设计、产品判断和用户体验之间的抽象层。AI 可以给你一个看起来不错的界面，却未必知道它是否解决了正确问题。

![访谈从 Codex 的产品流程谈到设计：AI 可以加速制作，但无法自动替代对“好”的判断。](images/03.jpg)

## 角色在塌缩，但角色能力没有消失

Codex 团队的工作方式里，一个明显变化是角色边界变模糊了。设计师会写代码，产品经理懂技术，工程师也需要产品判断。Andrew 把这描述成一种更灵活的协作状态。

但他并不赞成简单说“取消产品角色，所有人都变成 builder”。因为 PM、工程、设计各自仍然有专业能力，只是这些能力不再被岗位边界死死隔开。

在 Codex 这种产品里，团队更像区域防守。不是每个人只守一个固定位置，而是根据当前问题需要什么能力，谁就补上去。一个人可能这一周更像 PM，下一周更像工程，另一个时刻又在做产品一致性的判断。

这对 AI 时代的组织有启发：角色名称会变得松动，但专业能力不会消失。真正有价值的人，是能把想法从构思推进到完成，并且有品位判断它是否足够好的人。

## Codex 的目标，是成为工作中枢

访谈后半段谈到 Codex 和 ChatGPT 为什么要合并。Andrew 的逻辑是：Codex 在工程和研究工作流里找到了很强的内部产品市场契合，但很多非工程岗位的人，其实不适合直接使用原来的开发者界面。

既然法律、产品、研究、运营都开始需要这种 agent 能力，为什么不把 Codex 的经验带到更通用的入口里？比如 ChatGPT 桌面应用、浏览器、以及用户已经在使用的各种工具。

这就是“工作中枢”的含义。用户不应该为了让 AI 做事，在多个产品之间来回切换。未来的入口更可能是：你在一个地方开始工作，AI 根据任务需要去调动 ChatGPT、Codex、连接器、浏览器自动化、computer use，甚至外部应用。

![Codex 与 ChatGPT 的融合，不只是把两个名字放在一起，而是让 agent 能力进入更通用的知识工作场景。](images/04.jpg)

## computer use 和浏览器自动化，让 AI 进入真实工具

Codex 的一个重要转折，是应用内浏览器、computer use 和 artifact creation 的引入。它让 AI 不只是写代码，而是可以操作真实软件和网页，在工具之间完成任务。

访谈里提到一个有趣例子：制作人用 Codex 辅助视频剪辑，甚至让 Codex 为自己构建扩展。Codex 本身不是视频剪辑工具，但它可以理解目标、调用工具、补上缺失的桥梁。

这说明未来的软件边界会变得更松。你不一定需要每个工具都原生内置 AI；只要 agent 能理解目标、访问上下文、操作界面或调用连接器，它就能把现有工具编织成新的工作流。

## 未来的知识工作，是人和 agent 共同维护循环

Andrew 讨论了 loops 和 autonomous development，也就是让 AI 不只完成一次任务，而是参与持续循环：发现问题、提出方案、生成原型、收集反馈、继续改进。

这会改变产品工作，也会改变普通知识工作。过去我们把工作拆成“人想、工具执行”；现在更像是“人设定方向，agent 推进多个分支，人再判断和收敛”。

但这并不意味着人被移出流程。相反，人的判断更靠前也更关键：决定做什么，决定什么算好，决定哪些结果可以进入产品，哪些只是个人自动化。AI 能扩大行动半径，不能替你承担品位和责任。

![Andrew 对 Codex 的愿景，是一个能协调桌面、浏览器、连接器和工作工具的知识工作入口。](images/05.jpg)

## 写在最后

这期访谈最值得记住的，不是“Codex 会不会并进 ChatGPT”这个产品路线问题，而是它背后的工作方式变化。

当 AI 能写代码、做原型、操作浏览器、连接工具，产品开发和知识工作都会从线性流程，变成更快的探索循环。执行成本下降之后，真正稀缺的是品位、判断、问题定义和产品一致性。

Codex 和 ChatGPT 的融合，指向的不是一个更大的聊天框，而是一个新的工作入口：它既能聊天，也能行动；既能写代码，也能处理文档、研究、文件、浏览器和外部工具。知识工作的未来，可能不是人打开十个软件逐个切换，而是在一个 AI 工作中枢里，让 agent 帮你把任务推到下一步。
