# 2026-10-08 五组公众号长图双盲对比实验

## 实验目的

对五组同题公众号长图进行独立双盲评估，比较两组材料在内容质量、视觉证据和手机阅读体验上的差异。

本文件只记录实验设计、执行过程和结果，不属于用户版 Skill 的功能说明。本次实验没有修改 `youtube-to-weixin-article/SKILL.md`，也没有把评分流程封装进用户版 Skill。

## 实验时间

- 执行日期：2026-10-08
- 时区：Asia/Shanghai
- 独立评分任务：`双盲评测：5组公众号长图`
- 评分任务 ID：`01a11a45-3887-7612-9b30-a516a1b0f245`

## 实验材料

实验包含五个相同主题，每个主题各有 A、B 两份长图：

1. OpenAI 产品负责人如何做短周期产品规划；
2. OpenAI 联合创始人如何把工作逐步交给 AI；
3. YC 合伙人关于先联系一百个客户的建议；
4. OpenAI CEO 如何使用 AI 助手；
5. OpenAI DevDay 产品试用与限制。

为避免路径、文件名和项目结构泄露材料身份，主任务先把十张长图复制到中性目录，并统一改名为 `01.png` 至 `05.png`：

```text
outputs/blind_evals/20261008_latest5/材料A/
outputs/blind_evals/20261008_latest5/材料B/
```

独立评分窗口只获得以上两个目录，不获得原始文件位置、Skill、实验历史或材料身份。

出于版权和仓库体积考虑，本实验记录不上传原始公众号长图及匿名副本，只保存方法、评分和结论。

## 双盲设计

独立评分窗口被明确要求：

1. 不读取或参考其他对话、历史评分、Skill、项目说明、Git 记录或用户背景；
2. 只查看中性目录中的十张长图；
3. 全程只使用“材料 A”和“材料 B”，不推断两组来源；
4. 将 `01` 至 `05` 视为五组一一对应的同题材料；
5. 完整查看每张长图后再评分；
6. 不创建或修改文件，只提交最终评分报告。

评分完成后才由主任务揭盲：

- 材料 A：原资料长图；
- 材料 B：当前用户版 Skill 生成的长图。

## 评分标准

每篇满分 100 分：

| 维度 | 分值 |
| --- | ---: |
| 标题与开头 | 15 |
| 结构与论证 | 20 |
| 事实与具体细节 | 20 |
| 中文可读性 | 15 |
| 截图与段落贴合度 | 20 |
| 长图排版与手机阅读 | 10 |

评分窗口还被要求专项检查：

- 是否存在文字出框、标题裁断或字号过小；
- 截图是否能够证明附近观点，而不只是平均插图；
- 是否保留冲突、失败、等待、误判、成本和真实用户反馈；
- 来源是否清楚，是否错误显示本地文件名或磁盘路径。

## 执行过程

1. 核对两边各五张长图，并按主题建立一一对应关系。
2. 创建 A、B 两个中性目录，将文件统一改名为 `01.png` 至 `05.png`。
3. 新建独立评分任务，只发送匿名目录和统一评分标准。
4. 独立任务逐张打开十张完整长图，没有读取用户版 Skill 或既有实验结论。
5. 独立任务提交逐篇评分、平均分、专项检查和八条优化建议。
6. 主任务在评分完成后揭盲，确认 A 为原资料、B 为当前 Skill 结果。
7. 本次只归档实验结果，没有修改用户版 Skill。

## 主要发现

### 材料 A 的稳定优点

1. 正文字号和行距更适合手机直接阅读；
2. 五篇都保留了失败、等待、误判和限制等故事细节；
3. 来源通常同时包含节目、嘉宾、主持人和公开视频地址。

### 材料 A 的主要问题

1. 截图数量较少，且在部分文章中分布不均；
2. 公众号相关文章、收藏卡、账号介绍和重复文章头增加了非正文长度；
3. 长图篇幅偏长，重点层级和视觉变化不足。

### 材料 B 的稳定优点

1. 标题、引语、章节、截图、正文和来源形成了清楚的阅读路径；
2. 截图覆盖率与分布更好，主要章节普遍有视觉锚点；
3. 成品没有公众号导航、推荐文章和账号卡片等干扰信息。

### 材料 B 的主要问题

1. 1200 像素宽画布中的正文偏小，缩放到手机宽度后阅读压力较大；
2. 部分截图只是相关人物的谈话画面，不能直接证明附近的产品、界面或结果描述；
3. 图注表达重复，没有具体指出画面中的证据及其支持的观点。

## 专项检查结果

- 十张长图均未发现明显文字出框、标题裁断或图片越界。
- 第 03 组的证据型截图最完整，能够直接支持职位筛选、邮件内容和跟进过程。
- 第 01、04、05 组存在较多人物访谈帧，只能证明访谈场景，不能核验产品表现或具体结果。
- 两组都较完整地保留了冲突、失败、等待、误判、成本与限制；直接用户原话和量化反馈仍可加强。
- 两组均提供公开视频来源，没有把本地文件名或磁盘路径作为读者可见来源。

## 独立窗口提出的优化建议

以下建议只作为本次实验发现记录，尚未写入用户版 Skill：

1. 放大正文并增加行距，使用真实手机宽度检查阅读舒适度；
2. 用产品界面、真实反馈、文档或结果画面替换低信息量的人物谈话帧；
3. 重写模板化图注，说明画面中可见的证据以及它支持的具体观点；
4. 删除非正文尾部、重复文章头和账号组件；
5. 用“预期—受阻—处理—结果”的结构强化关键失败链条；
6. 缩短长标题和首屏引语，减少进入正文前的空间占用；
7. 每篇优先配置三至四张不同类型的证据图，避免相似人物帧机械分布；
8. 在公开来源之外补充发布日期、截图时间点或章节时间码，提高可核验性。

## 实验结论

揭盲后确认，材料 B 为当前用户版 Skill 生成结果。它在五组测试中全部胜出，平均领先 5.0 分，优势集中在结构、截图覆盖和成品整洁度。

这次结果也显示，当前版本并非所有维度都优于原资料：材料 A 的正文字号、行距和手机阅读舒适度更好。后续如需更新 Skill，应由用户单独确认具体建议；本次提交仅完成实验归档。
