# 同类 Skill 项目包装标准

后续同类 Skill 项目按这个标准整理，避免只有一个 `SKILL.md`，也避免为了好看而堆无意义文档。

## README 首页

README 必须先回答四个问题：

1. 这个 Skill 解决什么重复问题；
2. 使用者会得到什么具体交付物；
3. 它相比普通 Agent 的改进在哪里；
4. 有哪些实验、评分或评审证据可以复查。

README 可以有视觉封面，但不能只做装饰。项目价值、安装方式、使用示例、证据链和边界必须在首页清楚出现。

## 必备文档

| 文件 | 内容 |
| --- | --- |
| `PROJECT.md` | 项目定位、目标用户、能力边界、使用路径。 |
| `EXPERIMENT.md` | 实验组、测试组、样本来源、隔离方式、主要发现。 |
| `EVALUATION.md` | 评分标准、独立评分流程、写回规则。 |
| `SKILL_REVIEW.md` | 已发现问题、整改状态、发布检查。 |

## 推荐目录

| 目录 | 用途 |
| --- | --- |
| `references/` | 放稳定规则和可复用判断标准。 |
| `evals/` | 放每一轮独立评分、对照实验或评估摘要。 |
| `assets/readme/` | 放 README 使用的视觉资源。 |
| `scripts/` 或 Skill 内 `scripts/` | 放确定性工具，例如渲染、校验、打包脚本。 |

## 不能伪装的内容

- 没有做自动化测试，就不要写“已完成自动化 benchmark”。
- 没有独立评分，就不要写“已通过独立验证”。
- 单次偏好不能写成通用规则。
- 原始学习资料不能默认上传到公开仓库。

## 迭代流程

```text
新样本或新问题
        ↓
独立生成或独立评分
        ↓
记录到 evals/ 或 EXPERIMENT.md
        ↓
用户确认是否通用
        ↓
修改 Skill 和 references/
        ↓
校验、提交、推送
```
